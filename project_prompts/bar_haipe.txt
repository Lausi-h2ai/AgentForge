Optimized App Specification: BarHopper - Intelligent Bar Crawl Route Generator
Project Overview
A mobile-first progressive web application (PWA) that autonomously generates optimized bar crawl routes based on user preferences, location data, and intelligent pathfinding algorithms.

Core Features & Requirements
1. User Authentication & Profile Management

Authentication: Email/password and OAuth (Google, Apple)
User Profiles:

Saved preferences (drink types, atmosphere, price range)
Age verification (21+ in US, 18+ internationally)
Dietary restrictions/preferences
Accessibility needs


Privacy Settings: Location history opt-in/out, data retention preferences

2. Location & Mapping System

Primary Data Sources:

Google Places API (primary for venue data, reviews, hours)
OpenStreetMap/Mapbox (map rendering, routing)
Fallback to web scraping for missing data


Starting Point Options:

Current GPS location
Manual address entry
Saved locations (home, work, hotel)
Drop pin on map


Map Features:

Interactive map with bar markers
Route visualization with numbered waypoints
Real-time user location tracking during crawl
Street view integration



3. Venue Discovery & Filtering Engine

Data Collection:

Bar name, address, coordinates
Operating hours (with real-time open/closed status)
Rating (aggregate from Google, Yelp if available)
Price level ($ to $$$$)
Review count and recent reviews
Photos
Amenities (outdoor seating, live music, dance floor, food service)
Drink specialties (craft beer, cocktails, wine, sports bar)
Atmosphere tags (dive bar, upscale, casual, club, rooftop)
Current crowd level (if available via Google Popular Times)


Smart Filters:

Distance radius from starting point (0.5mi - 5mi)
Price range
Minimum rating threshold
Open now/specific time window
Amenity requirements (outdoor seating, food, live music)
Drink type preferences
Atmosphere/vibe
Avoid previously visited venues (toggle)
Include/exclude favorites (toggle)



4. Route Optimization Algorithm

Pathfinding Implementation:

Modified Traveling Salesman Problem (TSP) solver using:

Genetic Algorithm for larger route sets (7+ bars)
Dynamic Programming for smaller sets (≤6 bars)


Walking distance calculation via Mapbox/Google Directions API
Time estimation including:

Walk time between venues
Suggested duration at each bar (configurable: 30-90 min)
Total crawl duration display




Route Constraints:

User-specified number of stops (3-10 bars)
Maximum total walking distance
Return-to-start option OR end near transit
Time constraints (must finish by X time)
Pacing options (casual, moderate, fast-paced)


Ending Options:

Return to starting location
End near public transit (subway, bus, train stations)
End near rideshare pickup zones
End near user's home/hotel



5. Route Customization & Management

Pre-Generation Settings:

Number of stops
Total duration target
Start time (for real-time adjustments)
Force-include favorites
Exclude visited venues
Theme-based routes (craft beer tour, dive bars, upscale cocktails, LGBTQ+ friendly)


Post-Generation Edits:

Drag-and-drop reordering
Remove/add individual stops
Regenerate route with constraints
Lock specific venues in place while optimizing others


During Crawl:

Check-in at each venue (manual or location-based)
Skip venue (re-optimize remaining route)
Add spontaneous stop
Share live location with friends
Call rideshare directly from app



6. History & Favorites System

Route History:

Save all generated and completed routes
Metadata: date, starting location, venues visited, distance walked
Mark routes as "completed" vs "planned"
Add notes/photos to completed routes
Rating system for completed routes
Share past routes with friends


Favorites Management:

Star individual bars
Tag favorites with custom labels
Private notes on each favorite
"Must-visit" priority level for route generation
Create custom venue collections (e.g., "Best Rooftop Bars")


Smart Recommendations:

"You haven't been here" suggestions based on preferences
"Similar to your favorites" recommendations
Trending bars in your area
Seasonal/event-based suggestions



7. Social & Sharing Features

Group Planning:

Create group with invite links
Collaborative route voting
Group preferences aggregation
Split group mode (different preferences for subset of group)


Sharing:

Share route via link (view-only or editable)
Export to Google Maps/Apple Maps

8. Safety & Convenience Features

Safety:

Share live location with emergency contact
One-tap rideshare (Uber/Lyft integration)

Convenience:

Algorithm Implementation
Route Generation Flow:
1. Query venues within radius → filter by preferences
2. Score venues (rating × relevance × recency)
3. Select top N candidates (2-3× desired stops)
4. Generate distance matrix between all candidates
5. Apply TSP solver with constraints:
   - Start/end point requirements
   - Maximum total distance
   - Favorites must-include
6. Optimize for:
   - Minimum walking distance (60% weight)
   - Maximum aggregate rating (25% weight)
   - Variety of venue types (15% weight)
7. Return top 3 route options for user selection
Data Models
User Schema:
{
  id: UUID,
  email: string,
  passwordHash: string,
  profile: {
    name: string,
    dateOfBirth: date,
    preferences: {
      drinkTypes: array,
      priceRange: [min, max],
      atmospheres: array
    }
  },
  savedLocations: array,
  createdAt: timestamp
}
Venue Schema:
{
  id: UUID,
  placeId: string (Google),
  name: string,
  location: point (PostGIS),
  address: object,
  rating: float,
  priceLevel: int (1-4),
  hours: object,
  amenities: array,
  tags: array,
  photos: array,
  lastUpdated: timestamp
}
Route Schema:
{
  id: UUID,
  userId: UUID,
  name: string,
  status: enum (planned, in_progress, completed),
  startLocation: point,
  endLocation: point,
  venues: array [{
    venueId: UUID,
    order: int,
    duration: int,
    checkInTime: timestamp (nullable)
  }],
  totalDistance: float,
  totalDuration: int,
  createdAt: timestamp,
  completedAt: timestamp (nullable),
  rating: int (nullable),
  notes: text (nullable)
}
Favorites Schema:
{
  userId: UUID,
  venueId: UUID,
  tags: array,
  notes: text,
  priority: enum (normal, high),
  addedAt: timestamp
}
